# Acceptance tests (T1–T19)

From the production plan §14. All must pass on a physical iPhone and a physical Android phone before release; results are recorded here per build. The point of T2 is a screenshot: airplane-mode icon + empty network log + working app in one frame — the whole offline claim.

Preparation: install a development build (Expo Go cannot run MapLibre or Sign in with Apple), open the app once online so the feed and alerts are cached (Offline data → "Refresh everything now"), complete onboarding with a home area inside the pilot bbox, and have three test accounts ready: one Apple, one Google, one email. T12–T16 need a seeded preview project and a staff account (`scripts/grant-role.ts`). The console is `https://<host>/console`.

## State matrix — every screen must handle all nine

| State | Expected | Forbidden |
|---|---|---|
| Online · cache present | Render cache → refresh in background → replace quietly; status line "checked just now" | Full-screen spinner, list flicker |
| Offline · cache present | Render cache + OFFLINE banner + "Reports saved N min ago"; writes queue with "will send when online" | Error dialog, blank screen, a write that silently disappears |
| Offline · no cache | Empty state that says the phone has no saved reports yet; drafting still works; map draws attribution and no pins | "Check your connection" and nothing else |
| Online · cache expired (> 5 min feed, > 60 min forecast) | Render + refresh immediately; amber "forecast older than 60 min" on scenario cards | Old data presented as current |
| Signed out | Browse everything; vote / comment / follow / report controls open S-14 on tap and keep the draft; Me shows "Sign in to vote and follow" | Sign-in wall before browsing, lost draft |
| No reports nearby | Index card with "no open reports in your area", feed empty state with "Report what you see"; map renders | Fake urgency, demo data unlabelled, blank list |
| Low storage | Keep drafts, prefs, session and alerts; drop feed cache then sent-draft photos first; say what was dropped in Offline data | Silent failure, crash, a draft dropped |
| Camera / photo permission denied | Capture screen explains, offers Settings and the library; the report can still be filed without a photo | Dead shutter, crash, loop of permission prompts |
| No map tiles (offline, provider down, or style URL wrong) | Plain background, cached pins, "Map tiles unavailable" status line, attribution still visible | Blank map, pins missing because tiles failed, hidden attribution |

## Demo script (judging video)

1. Offline data → Demo & testing → **Storm**. Home: a blue scenario card names tonight's rain, the hour, and the storm-sensitive open reports in your watch area, labelled "rules-based: forecast × open backlog · demo". Below it, the neighbourhood index with its named drivers — "what has been reported, weighted by score — not a prediction".
2. Report tab — one tap to the camera. Photograph a lifted sidewalk slab. Analysis proposes a sidewalk sub-type with its confidence and shows a duplicate candidate a few metres away ("Add to that report" would attach the photo and count as a vote). Continue to the form: "How dangerous right now?" → Someone will fall; "Has anyone been hurt?" → Near miss; identity Initials. Submit → the sign-in sheet (Apple, two taps) → the draft is still there → Submitted: the score, its five bars, the rank among open sidewalk orders, the SLA timeline.
3. Tap **Why this score?**: five terms × five weights = the number on screen; the storm multiplier is shown separately; the AI read is marked "proposal — corrected by you". A formula, not a model.
4. Airplane mode ON → force-quit → relaunch. Every tab opens from the cache with the OFFLINE banner; the Map shows the saved pins without tiles. File a second report: "Saved on this phone · sends when online". Airplane OFF → it sends exactly once and gets its rank. This is the whole claim.
5. Console (`<host>/console`): the same report at the top of the triage queue with the same five bars. The inspector confirms severity (the reason goes to `severity_audit`), logs a mitigation ("cold patch") — the liability clock stops at that timestamp — and the phone receives "Made safe temporarily", which deep-links to the report.
6. Demo & testing → **Verify**: a completed report asks the reporter "Was it fixed?" beside the crew's after-photo → Confirm → "Fix confirmed by a resident". Me tab: reports filed / resolved / votes cast and median days-to-resolve vs citywide.

## Deep links

`rootcause://?demo=storm` (also `calm`, `verify`) · `rootcause://report/<id>` · `rootcause://map?cat=vegetation` (also `roadway`, `sidewalk`, `drainage`, `lighting`) · `rootcause://auth/callback` (email sign-in return).
